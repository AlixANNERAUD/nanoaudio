# Benchmarks

Numbers to help pick a codec and a configuration. They come from `tools/bench`, are regenerated with `python3 tools/bench/run.py`, and are only as good as the machine they ran on: compare rows with each other rather than trusting absolute values.

- Commit: `144a60f` for every row except G.711 and Opus, `c67aab2` for the G.711 rows, 2026-10-15, and `82764de` for the Opus rows, 2026-10-20.
- Host: Apple M2 Pro, macOS-27.0.1 (`aarch64-apple-darwin`).
- Toolchain: rustc 1.99.0 (b940084d7 2026-09-28), wasmtime 49.0.3 (f96eabaa1 2026-10-14).
- Method: each measurement repeats the whole operation until it lasts at least 40 ms, then takes the median of 11 such runs after a warm-up run, over 2 passes averaged.
- Noise: the median interquartile range is 1.2 % of the median, and the largest difference between passes is 8 %. The load average was 4.9 on 12 cores when the run started, so treat differences under 5 % as noise.

The test signal is generated by `tools/bench/src/signal.rs`: 4 seconds of chords with harmonics and vibrato, low-passed noise and decaying noise bursts every quarter second, around -18 dBFS RMS. FLAC, MP3 and Opus files are encoded from the same signal at benchmark time, with libsndfile and LAME through `uv` (Opus from a 48 kHz rendering of it).

FLAC needs one `i32` per sample of its largest block for every channel, or one `i16` with `i16` blocks for streams of up to 16 bits: pick `MAXIMUM_BLOCK_SIZE` and `MAXIMUM_CHANNELS` to match your files (most encoders use 4096 samples), and give it an input window of at least the largest frame. The MP3 input window defaults to 4 KiB and can be lowered with `Mp3Decoder::with_minimum_input`, down to the largest frame plus the next header (1,445 bytes for Layer III, whose largest frame is 1,441 bytes at 320 kbit/s and 32 kHz; free-format streams need twice their frame size plus 5 bytes); the bit reservoir is kept inside the decoder state. The FLAC input shown is the bound computed from the test file's header. Opus keeps the opus-rs decoder state, about 175 KB, one packet of up to 8 KiB and one decoded packet in `f32`, 45 KiB for the 120 ms Opus allows or 7.5 KiB for the 20 ms most encoders write (`OpusDecoder<i16, 960>`); its input is one whole Ogg page, the largest of the test file here, and pages can reach 65,307 bytes.

## Embedded CPU

No embedded hardware was used, so there are no cycle counts here. The host numbers rank the codecs, but the gap between them changes on a microcontroller: MP3 and Opus decode in floating point, emulated in software on cores without an FPU, and SBC (like FLAC on high-resolution streams) uses 64-bit products, which take several instructions on a 32-bit core, while G.711, IMA ADPCM, G.722 and QOA decoding stay in 32-bit integers. Measure on the target before committing to a codec close to your CPU budget.

### Resampling

Interleaved stereo `f32` in and out, 4 seconds of the test signal, in nanoseconds per input sample. Every resampler is built once and reset before each run, except dasp's, which its API builds around the signal; rubato goes through `process_all_into_buffer` with 1024-frame chunks.

### Sample operations

The DSP operations of the section above, against dasp's per-sample `Sample` methods, in nanoseconds per sample.

| Operation | Library | ns/sample |
| --- | --- | --- |
| Volume, i16 slice | nanoaudio-dsp, `Fixed` | 0.09 |
|  | nanoaudio-dsp, `Float` | 0.13 |
|  | dasp 0.11, `mul_amp` | 0.10 |
| Mix, i16 slice, second input at 80 % (includes a copy to reset the output) | nanoaudio-dsp, `Fixed` | 0.12 |
|  | nanoaudio-dsp, `Float` | 0.22 |
|  | dasp 0.11, `add_amp` + `mul_amp` | 0.13 |
| i16 slice to f32 slice | nanoaudio-dsp `convert` | 0.06 |
|  | dasp 0.11, `to_sample` | 0.06 |
| f32 slice to i16 slice | nanoaudio-dsp `convert` | 0.07 |
|  | dasp 0.11, `to_sample` | 0.06 |

dasp's `f32` to `i16` conversion truncates toward zero, while nanoaudio rounds to the nearest value, and dasp's `add_amp` wraps around on overflow where nanoaudio saturates.

## Reproducing

```sh
python3 tools/bench/run.py
```

It needs `rustup` targets `wasm32-wasip1`, `thumbv6m-none-eabi`, `thumbv7em-none-eabihf` and `riscv32imc-unknown-none-elf`, `wasmtime` for the WebAssembly rows, `uv` to encode the FLAC and MP3 test files, and on Apple silicon the `x86_64-apple-darwin` target and Rosetta 2 for the x86_64 rows. Use `--help` to skip parts. Close other applications first: the numbers move with load, thermal state and power settings.
