# Releasing

Releases are automated with [release-plz](https://release-plz.dev) using a Release PR flow.

## Flow

1. Changes are merged to `main`. CI runs, nothing is published.
2. The `Release` workflow opens or updates a Release PR that bumps the version, updates `CHANGELOG.md` and `Cargo.lock`.
3. Review the Release PR. Edit the version or the changelog in the PR if needed.
4. Merge the Release PR when a release is wanted. The `Release` workflow then validates the workspace (`cargo test --workspace --all-features`, `cargo package --workspace`), publishes every crate whose version changed to crates.io, and creates the tags and the GitHub release.

Ordinary merges never publish: `release_always = false` restricts publishing to merged Release PRs. If validation fails, nothing is published.

## Workspace

The repository is a Cargo workspace: the `nanoaudio` facade in `crates/nanoaudio` and one crate per codec or building block in `crates/nanoaudio-*`. Each crate has its own version and is released on its own:

- `nanoaudio` is tagged `vX.Y.Z`, gets a GitHub release, and its changelog is the root `CHANGELOG.md`, which also lists the changes of the other crates.
- Every other crate is tagged `<crate>-vX.Y.Z`, has no GitHub release, and keeps its changelog in `crates/<crate>/CHANGELOG.md`.

New crates start at `0.1.0` and are published as is by their first Release PR. Crates are published in dependency order, so `nanoaudio-core` goes first.

## SemVer policy

Pull requests are squash-merged, so each pull request title becomes one commit on `main`. The `PR Title` workflow requires titles to follow [Conventional Commits](https://www.conventionalcommits.org) (`feat: ...`, `fix: ...`, `feat!: ...`). Merge commits and release commits are left out of the changelog.

The proposed bump is derived from these commits since the last release:

| Commit | `>= 1.0.0` | `0.x.y` |
| --- | --- | --- |
| `fix:` and other types | patch | patch |
| `feat:` | minor | patch |
| `feat!:`, `fix!:` or `BREAKING CHANGE:` footer | major | minor |

The maintainer has the final say and may change the version in the Release PR.

[cargo-semver-checks](https://github.com/obi1kenobi/cargo-semver-checks) is disabled for now: release-plz runs it with every feature enabled, and the published 0.1.0 does not build that way (its `fixed` and `float` features were mutually exclusive). Re-enable `semver_check` in `release-plz.toml` once a release without that restriction is published.

## Changelog

Changelogs are generated by release-plz with git-cliff using the `[changelog]` section of `release-plz.toml`, and the entry for the release is used as the Release PR content and, for `nanoaudio`, the GitHub release body.

## Required setup

- Repository secret `CARGO_REGISTRY_TOKEN`: a crates.io API token with the `publish-new` and `publish-update` scopes.
- Settings > Actions > General > Workflow permissions: enable "Allow GitHub Actions to create and approve pull requests". Alternatively, replace `GITHUB_TOKEN` in the `release-plz-pr` job with a personal access token, which also lets CI run on the Release PR (pull requests opened with `GITHUB_TOKEN` do not trigger other workflows).
